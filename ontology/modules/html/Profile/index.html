1. Introduction

The Profile module models the actors within the GoTriple ecosystem. It defines `triple:Profile` for describing researchers and organizations, aligning them with `foaf:Person` and `foaf:Organization`. It also manages User Accounts (`foaf:OnlineAccount`) and their association with profiles to handle platform access and identity. Since iteration 19 the profile also carries personal names, self-description, pronouns, photo, personal web pages, disciplines of interest, thesaurus keywords, known languages, affiliation, registration and collaboration flags, the date of the last GoTriple update, and several identifiers kept apart by their scheme: the internal Elasticsearch id, the ARK minted by GoTriple, the OPERAS/GoTriple id and the external person PIDs (ORCID, IdRef, ISNI, ResearcherID). Which of these are mandatory is expressed in the SHACL shapes, not in OWL.

schema:knowsAbout op back to ToC

IRI: https://schema.org/knowsAbout

A topic the agent knows about. Schema.org declares it for Person and Organization, so it is in domain here: every triple:Profile is a person or an organization. It carries the concepts of the TRIPLE Vocabulary (SSH-LCSH) the user declares to know about. The data model revision leaves this field unmapped: the choice of this property is the ontology own.

schema:url op back to ToC

TRIPLE Internal ID ni back to ToC

IRI: https://gotriple.eu/ontology/triple/internal_id_schema

Identifier scheme of the internal identifier assigned by the GoTriple platform to a resource. Declared in the TRIPLE namespace because datacite:local-resource-identifier-scheme cannot distinguish an identifier local to GoTriple from one local to the source system. On profiles it carries the Elasticsearch id.

belongs to
datacite:IdentifierScheme c
