# Ontology metadata and serialization

Reference for the `samod` skill: the full metadata block a standalone serialization must carry, and the version-management rules. Moved out of the root `CLAUDE.md` on 2026-07-31 so it loads only when it is needed.


When creating or updating the final ontology serialization, include comprehensive metadata to ensure proper documentation and discoverability.

**Source of truth**: shared ontology metadata lives in `ontology/metadata.ttl` (currently `owl:versionInfo "2.2.0"`), consumed by `scripts/build.py` when compiling vocabularies **and** by `scripts/merge_iterations.py` when writing the consolidated `ontology/triple.ttl`. Update version/dates there first; the template below shows the full metadata shape for standalone serializations.

### Required Header Comment
Add a header comment at the top of the serialization file with:
```turtle
# TRIPLE Ontology - GoTriple Platform Data Model
# Version: [current_version]
# Last Modified: [date]
# License: CC BY 4.0
# Website: https://gotriple.eu/ontology/triple
# Generated using SAMOD methodology
# Merged from [number] SAMOD iterations (development/01 through development/[latest])
```

### Comprehensive Ontology Metadata
The ontology declaration should include these metadata properties:
```turtle
<https://gotriple.eu/ontology/triple> rdf:type owl:Ontology ;
    owl:versionIRI <https://gotriple.eu/ontology/triple/[version]> ;
    owl:versionInfo "[version]" ;
    rdfs:label "TRIPLE Ontology"@en ;
    rdfs:comment "Comprehensive semantic representation of the GoTriple discovery platform's data model for Social Sciences and Humanities (SSH) research artifacts."@en ;
    dcterms:title "TRIPLE Ontology - GoTriple Platform Data Model"@en ;
    dcterms:description "This ontology provides a formal model for representing scholarly resources in the Social Sciences and Humanities domain within the GoTriple discovery platform. It includes classes and properties for documents, datasets, authors, projects, identifiers, and their relationships."@en ;
    dcterms:creator "Alessandro Bertozzi" ;
    dcterms:contributor "Luca De Santis", "Silvio Peroni" ;
    dcterms:publisher "GoTriple" ;
    dcterms:license <https://creativecommons.org/licenses/by/4.0/> ;
    dcterms:rights "This work is licensed under Creative Commons Attribution 4.0 International License" ;
    dcterms:subject "Social Sciences and Humanities", "Research Data", "Scholarly Communication", "Semantic Web" ;
    dcterms:language "en" ;
    dcterms:format "application/rdf+xml", "text/turtle" ;
    dcterms:created "[creation_date]" ;
    dcterms:modified "[last_modified_date]" ;
    dcterms:source <https://github.com/GoTriple/triple-ontology> ;
    schema:url <https://gotriple.eu/ontology/triple> ;
    schema:version "[version]" ;
    rdfs:seeAlso <https://gotriple.eu/>, <https://www.samod.org/> ;
    owl:priorVersion <https://gotriple.eu/ontology/triple/[previous_version]> ;
    vann:preferredNamespacePrefix "triple" ;
    vann:preferredNamespaceUri "https://gotriple.eu/ontology/triple/" ;
    dcterms:bibliographicCitation "Bertozzi, A., De Santis, L., & Peroni, S. ([year]). TRIPLE Ontology - GoTriple Platform Data Model (Version [version]). GoTriple. https://gotriple.eu/ontology/triple" ;
    schema:citation "Bertozzi, A., De Santis, L., & Peroni, S. ([year]). TRIPLE Ontology - GoTriple Platform Data Model (Version [version]). GoTriple. https://gotriple.eu/ontology/triple" ;
    dcat:keyword "ontology", "semantic web", "social sciences", "humanities", "research data" .
```

### Footer Attribution
End the serialization file with:
```turtle
###  Generated by Claude Code on [date]
###  Merged from [number] SAMOD iterations (development/01 through development/[latest])
```

### Version Management
- Update version numbers consistently across all metadata fields
- **Mint `owl:versionIRI <https://gotriple.eu/ontology/triple/{X.Y.Z}>` at the release
  chore** (URI-CONVENTIONS §6; the semver pattern is reserved in the term space)
- Include `owl:priorVersion` pointing to the previous versionIRI
- Update modification dates when making changes
- Record every substantive change as a dated entry in `CHANGELOG.md` (format documented at the top of that file: Date, Iteration, Type, Description, Author)
- At release: regenerate the documentation (`scripts/build_docs.sh ontology/html` —
  all seven pages: model + six vocabularies, serializations included),
  tag, publish the GitHub release — the release archive is what deployment unpacks as
  the frozen `/ontology/triple/{X.Y.Z}` snapshot (see `ontology/html/README.md`,
  "Versioned snapshots")
